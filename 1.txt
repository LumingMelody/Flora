这是一个很好的架构优化方向。让我先分析当前问题，然后提出方案。

  当前问题分析

  现状：
  1. Plan 一旦生成就固定，执行过程中无法调整
  2. 重试机制僵化（ResultAggregator 只做 HTTP 500 等简单重试）
  3. 缺乏执行过程中的"观察-反馈-调整"能力

  期望：
  - 支持动态分支执行
  - 执行中可增量重规划
  - 智能重试（理解失败原因后调整策略）

  ---
  方案设计

  方案一：分支计划 + 条件执行

  核心思路：Plan 阶段生成带条件分支的计划，TaskGroupAggregator 根据执行结果选择分支。

  Plan 结构：
  [
    { step: 1, executor: "A", ... },
    { step: 2, executor: "B",
      branches: [
        { condition: "step_1.status == 'SUCCESS' && step_1.result.count > 0",
          next_steps: [3, 4] },
        { condition: "step_1.result.count == 0",
          next_steps: [5] },  // 跳过某些步骤
        { condition: "step_1.status == 'FAILED'",
          next_steps: [], fallback: "retry_with_different_params" }
      ]
    },
    ...
  ]

  优点：
  - 预先规划好分支，执行效率高
  - 适合可预见的业务分支

  缺点：
  - 无法应对完全意外的情况
  - Plan 复杂度增加

  ---
  方案二：Monitor + 增量重规划

  核心思路：引入 Monitor 角色，观察执行过程，发现问题时触发增量重规划。

  架构：
                      ┌─────────────┐
                      │   Monitor   │ ← 观察所有步骤结果
                      └──────┬──────┘
                             │ 发现问题
                             ▼
  ┌──────────┐    ┌─────────────────┐    ┌──────────────┐
  │ Planner  │◄───│ TaskGroupAggr   │───►│ Executor     │
  └──────────┘    └─────────────────┘    └──────────────┘
       │                   ▲
       │ 增量 Plan         │ 插入新步骤
       └───────────────────┘

  Monitor 职责：
  1. 观察每步执行结果
  2. 判断是否需要干预（失败、结果异常、偏离预期）
  3. 触发增量重规划或智能重试

  增量重规划：
  # Monitor 发现问题后
  new_steps = planner.replan_from_step(
      current_step=3,
      failure_reason="数据库连接超时",
      context=step_results,
      remaining_steps=[4, 5, 6]
  )
  # 可能的结果：
  # - 插入重试步骤（换个数据源）
  # - 跳过后续步骤
  # - 替换执行策略

  优点：
  - 高度灵活，能应对意外情况
  - 符合 ReAct 思想

  缺点：
  - 每次干预都需要 LLM 调用，成本高
  - 可能导致执行时间不可预测

  方案三：混合方案（推荐）

  核心思路：结合方案一和方案二，分层处理不同类型的问题。

  ┌─────────────────────────────────────────────────────────────┐
  │                      Plan 层（静态分支）                      │
  │  - 预定义的业务分支（if-else）                                │
  │  - 预定义的降级策略（fallback）                               │
  └─────────────────────────────────────────────────────────────┘
                                │
                                ▼
  ┌─────────────────────────────────────────────────────────────┐
  │                TaskGroupAggregator（执行层）                  │
  │  ┌─────────────┐  ┌─────────────┐  ┌─────────────────────┐  │
  │  │ 分支选择器   │  │ 智能重试器   │  │ Monitor（轻量观察）  │  │
  │  └─────────────┘  └─────────────┘  └─────────────────────┘  │
  │        │                │                    │              │
  │        │                │                    │ 严重问题     │
  │        ▼                ▼                    ▼              │
  │   执行预定义分支    智能调整参数重试      触发增量重规划      │
  └─────────────────────────────────────────────────────────────┘
                                │
                                ▼
  ┌─────────────────────────────────────────────────────────────┐
  │                ResultAggregator（底层重试）                   │
  │  - HTTP 500/超时等基础重试                                    │
  │  - 指数退避                                                  │
  └─────────────────────────────────────────────────────────────┘

  三层重试/调整机制
  ┌───────────┬─────────────────────┬────────────────────────────────┬────────────────────────────┐
  │   层级    │      负责组件       │            处理场景            │            策略            │
  ├───────────┼─────────────────────┼────────────────────────────────┼────────────────────────────┤
  │ L1 底层   │ ResultAggregator    │ HTTP 500、超时、网络抖动       │ 简单重试 + 指数退避        │
  ├───────────┼─────────────────────┼────────────────────────────────┼────────────────────────────┤
  │ L2 智能   │ TaskGroupAggregator │ 参数错误、权限不足、资源不存在 │ 分析错误 → 调整参数 → 重试 │
  ├───────────┼─────────────────────┼────────────────────────────────┼────────────────────────────┤
  │ L3 重规划 │ Monitor + Planner   │ 业务逻辑失败、策略失效         │ 增量重规划                 │
  └───────────┴─────────────────────┴────────────────────────────────┴────────────────────────────┘

  2. TaskGroupAggregator 智能重试

  class TaskGroupAggregator:

      def _handle_step_failure(self, step, error, context):
          """智能重试处理"""

          # 分析错误类型
          error_analysis = self._analyze_error(error)

          if error_analysis.type == "PARAM_ERROR":
              # 参数错误：尝试修正参数后重试
              fixed_params = self._fix_params_with_llm(
                  original_params=step.params,
                  error_message=error.message,
                  context=context
              )
              return self._retry_with_params(step, fixed_params)

          elif error_analysis.type == "RESOURCE_NOT_FOUND":
              # 资源不存在：尝试查找替代资源
              alternative = self._find_alternative_resource(
                  resource_type=error_analysis.resource_type,
                  context=context
              )
              if alternative:
                  return self._retry_with_resource(step, alternative)
              else:
                  return self._trigger_replan(step, error)

          elif error_analysis.type == "PERMISSION_DENIED":
              # 权限不足：尝试降级执行或跳过
              if step.has_fallback:
                  return self._execute_fallback(step)
              else:
                  return self._skip_and_continue(step)

          else:
              # 未知错误：触发增量重规划
              return self._trigger_replan(step, error)

  3. Monitor 轻量观察

  class ExecutionMonitor:
      """轻量级执行监控器"""

      def __init__(self, planner, threshold=0.7):
          self.planner = planner
          self.anomaly_threshold = threshold
          self.step_history = []

      def observe(self, step_result):
          """观察步骤结果"""
          self.step_history.append(step_result)

          # 轻量检查（不调用 LLM）
          anomaly_score = self._quick_anomaly_check(step_result)

          if anomaly_score > self.anomaly_threshold:
              # 触发深度分析（调用 LLM）
              return self._deep_analysis(step_result)

          return None  # 正常，无需干预

      def _quick_anomaly_check(self, result):
          """快速异常检测（规则基础）"""
          score = 0

          # 检查执行时间异常
          if result.duration > result.expected_duration * 2:
              score += 0.3

          # 检查结果为空
          if result.data is None or result.data == {}:
              score += 0.4

          # 检查连续失败
          recent_failures = sum(1 for r in self.step_history[-3:] if r.status == "FAILED")
          if recent_failures >= 2:
              score += 0.5

          return score

      def _deep_analysis(self, result):
          """深度分析（LLM）"""
          analysis = self.planner.analyze_execution_state(
              current_result=result,
              history=self.step_history,
              remaining_plan=self.remaining_steps
          )

          if analysis.recommendation == "REPLAN":
              return {
                  "action": "REPLAN",
                  "reason": analysis.reason,
                  "suggested_changes": analysis.changes
              }
          elif analysis.recommendation == "SKIP":
              return {
                  "action": "SKIP",
                  "skip_steps": analysis.skip_steps
              }

          return None
